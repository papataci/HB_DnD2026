Ink command convention
=======================
Engine commands are authored as a line starting with "@COMMAND:", the "@"
marking it as an out-of-band directive rather than a character speaking (see
the plain "Speaker: text" dialogue form, e.g. "Toshiro: ..."). The grammar
(prefix, argument counts, name lookups) lives in ink/ink_commands.gd and is
used both at runtime (ink/ink_starter.gd) and by the launch-time content
check (_globals/content_check.gd), which reports unknown commands, wrong
argument counts, unknown names and missing knots in the Output panel as soon
as the game starts - so run the game once after editing ink and look there.

When you add a new command, add it to InkCommands.ARITY, handle it in
ink_starter.gd, and add it to this list.

Names are case-insensitive. Sublocations are named by their
ENUMS.SUBLOCATIONS key (_globals/enums.gd): note "room01" but "room_int_01".

@MCP: <text>
	Shows <text> in a ShellMessage panel (ui/shell_message.tscn), styled as
	a system/narrator message, and waits for the player to dismiss it before
	the story continues. The whole rest of the line is the text.
	Example: @MCP: This room is empty, go back to work!

@CUTSCENE: <name>
	Plays the cutscene registered under <name> in
	CutsceneManager.CUTSCENES (_globals/cutscene_manager.gd) full-screen,
	and waits for it to finish before the story continues.
	Example: @CUTSCENE: holly_awakes

@TELEPORT: <target>
	Moves every playable character currently present into <target>, then
	plays the same fade as walking there. <target> is either:
	  - a key in ENUMS.LOCATIONS (e.g. "morlako"): everyone returns to the
		top-level map, fully exiting any (possibly nested) sublocation. Only
		one location exists today, so which name was given doesn't matter
		yet - it's still required to be a real one.
	  - a key in ENUMS.SUBLOCATIONS (e.g. "reception"): that sublocation is
		shown as a fresh top-level entry, so its back arrow leads to the map.
	Example: @TELEPORT: reception
	Example: @TELEPORT: morlako

@INTRO: <Character>
	Plays ui/char_intro.tscn full-screen, showing <Character>'s portrait
	(CharacterData.bubble_texture), name (character_name), and intro text
	(char_intro), and waits for it to finish before the story continues.
	<Character> is a key in ENUMS.CHARACTERS and must have a CharacterData
	entry in Character.DATA (draggables/character.gd) with those fields
	filled in to display anything meaningful.
	Example: @INTRO: toshiro

@SET_KNOT: <knot>
@SET_KNOT: <target> <ink_story> <knot>
	Records in WorldState (_globals/world_state.gd) where a sublocation's or
	a location's story resumes the next time it's entered/returned to - e.g.
	put this at the end of a quest-step knot so the room doesn't replay the
	same scene on the next visit, or at the end of a location's own story
	(see @RESOLVE_ROOM and LocationManager) so it doesn't replay either.
	Because that state lives in WorldState rather than on scene nodes, the
	target doesn't need to be loaded, and the command works the same before
	or after a @TELEPORT.
	The 1-argument form is shorthand for "SELF - <knot>": move the story
	this line is in, for whatever it's attached to, to <knot>.
	The 3-argument form can also move a *different* room's or location's
	story, or switch which ink story it plays:
	  <target> is a key in ENUMS.SUBLOCATIONS, a key in ENUMS.LOCATIONS, or
	  the literal keyword SELF for whatever this story is attached to.
	  <ink_story> is a key in InkRegistry.INK_STORIES
	  (_globals/ink_registry.gd), or "-" to keep the current story.
	  <knot> is the knot to resume from, or "-" for InkCommands.DEFAULT_KNOT
	  ("Start") - the convention every room-quest ink file uses for its
	  opening knot.
	Synchronous - doesn't pause the story like the other commands.
	Example: @SET_KNOT: LeaveMeAlone
	Example: @SET_KNOT: room01 room_default RoomAlreadyClean
	Example: @SET_KNOT: morlako time_scheduler Day02MorningEnd
	Example: @SET_KNOT: SELF - -

@CLOSE:
@CLOSE: <sublocation>
@OPEN:
@OPEN: <sublocation>
	Sets whether <sublocation> is open in WorldState
	(_globals/world_state.gd) - e.g. sublocation/backgrounds/room_door_open.gd
	reads this to show/hide a room's open-door sprite. <sublocation> is a key
	in ENUMS.SUBLOCATIONS, or the literal keyword SELF for the sublocation
	this story is attached to - same argument form as @SET_KNOT's. If
	omitted, defaults to SELF (the current room). Like @SET_KNOT, this is
	state in WorldState, not on a scene node, so the target doesn't need to
	be loaded, and it works before or after a @TELEPORT alike. Synchronous -
	doesn't pause the story.
	Example: @CLOSE:
	Example: @OPEN: room01

@RESOLVE_ROOM:
@RESOLVE_ROOM: <sublocation>
	Clears <sublocation>'s "Unresolved" flag in WorldState
	(_globals/world_state.gd) - e.g. drop_zones/char_bubble.gd reads this to
	show/hide a room's Unresolved sprite. <sublocation> is a key in
	ENUMS.SUBLOCATIONS, or the literal keyword SELF for the sublocation this
	story is attached to - same argument form as @SET_KNOT's. If omitted,
	defaults to SELF (the current room). Like @SET_KNOT and @CLOSE/@OPEN,
	this is state in WorldState, not on a scene node, so the target doesn't
	need to be loaded, and it works before or after a @TELEPORT alike.
	Synchronous - doesn't pause the story.
	Example: @RESOLVE_ROOM:
	Example: @RESOLVE_ROOM: room01
